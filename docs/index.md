# 操作系统课程实验

复旦大学 **2026 年秋季学期《操作系统（H）》** 课程配套实验。

实验配套代码仓库：[OS-26Fall-FDU](https://github.com/rfieldsy/OS-26Fall-FDU)

## 整体实验目标

本课程实验以 AArch64 多核平台为基础，在 QEMU 中逐步构建一个能够运行用户程序并通过 shell 交互的教学操作系统。通过亲手实现内存分配、进程管理、地址空间与上下文切换、同步互斥、设备驱动、块缓存和文件系统，并将它们与系统调用、程序加载、终端和管道连接起来，理解**操作系统如何把硬件资源组织成程序可以安全、有效使用的运行环境**。

随着实验推进，希望同学们逐步形成以下能力：

- **建立从硬件到应用的整体认识**：理解内核如何启动，如何借助处理器的特权级、页表、中断与异常支持程序运行，并能解释一条 shell 命令从输入、加载、执行到产生输出的完整过程。
- **理解资源管理与抽象的关系**：把进程、虚拟地址空间、文件和文件描述符与底层 CPU、内存及设备联系起来，掌握资源分配、共享、隔离和回收的基本方法，理解效率、公平性与实现复杂度之间的取舍。
- **围绕正确性组织系统实现**：在多核并发、进程切换和异步 I/O 中维护共享状态及资源生命周期；理解缓存、日志和文件系统如何配合，以及它们在故障恢复中能够提供的保证及其前提。
- **形成系统分析与调试能力**：结合源码、接口约定、状态变化和实验现象解释实现，使用测试和调试证据定位问题，并说明实现的适用范围与局限。使用大模型辅助时，也能核对建议、解释取舍，对最终实现作出自己的判断。

## 贯穿实验的五个问题

以下问题可以带着做完整个课程实验，不必在开始时就给出完整答案。随着对系统的理解加深，尝试用自己的实现和观察到的现象不断补充、修正答案。

1. **操作系统为程序提供了什么，为什么需要这些抽象？** 从直接操作硬件到使用进程、地址空间和文件，程序获得了哪些便利与保证？这些保证分别依靠哪些硬件能力和内核机制建立？

2. **有限的资源如何被多个程序安全而有效地共享？** 操作系统如何决定资源分配给谁、使用多久、何时回收，如何限制程序之间的相互影响，又如何允许必要的通信与共享？这些选择如何影响效率、公平性和隔离性？

3. **执行顺序不可预测时，系统怎样仍然保持正确并持续推进？** 多核执行、中断和阻塞会让哪些看似连续的操作被打断？哪些状态必须始终满足约束，如何既避免竞态，又避免死锁、丢失唤醒或无限等待？

4. **数据何时才算真正保存，发生故障后怎样维持一致的状态？** 程序看到写入成功、数据进入缓存和数据持久化之间有什么区别？当一组更新只完成一部分时，系统如何判断哪些结果应该保留，并恢复到可以继续使用的状态？

5. **一条 shell 命令背后，整个操作系统如何协同工作？** 从接收输入到程序执行、访问文件或设备，再到输出结果和回收资源，控制权与数据经过了哪些边界？如果其中一环出错，如何沿这条链路定位原因，又如何判断各模块组合后仍然正确？

## 实验安排

下表为 13 周的相对进度安排，具体教学周由课程公告确定。

| 实验 | 内容 | 周期 | 相对进度 | 状态 |
| --- | --- | --- | --- | --- |
| [Lab0 · Booting](./lab/lab0.md) | 配置并启动操作系统内核 | 1 周 | 第 1 周 | 已发布 |
| Lab1 · Memory Allocator | 实现物理内存的分配管理 | 2 周 | 第 2–3 周 | 待发布 |
| Lab2 · Process (Kernel Part) | 实现内核态的进程管理 | 2 周 | 第 4–5 周 | 待发布 |
| Lab3 · Process (User Part) | 实现用户态页表和上下文切换机制 | 2 周 | 第 6–7 周 | 待发布 |
| Lab4 · Condvar & VirtIO Driver | 理解同步互斥原语与初始化块设备驱动 | 1 周 | 第 8 周 | 待发布 |
| Lab5 · Logging File System | 实现磁盘管理与块缓存 | 1 周 | 第 9 周 | 待发布 |
| Lab6 · Inode-based FS | 实现基于 Inode 的文件系统 | 2 周 | 第 10–11 周 | 待发布 |
| LabFinal | 实现 Pipe、Console、ELF 加载等功能，最终启动 shell | 2 周 | 第 12–13 周 | 待发布 |
